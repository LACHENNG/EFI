# 操作明细 · 从 Windows 到 macOS 再回来（约 12–15 分钟）

> 目标：装上优化后的 EFI → 进 macOS 验收核显加速/硬解 → 回 Windows 把报告带给我。
> 原则：**只重启两次**（Windows→macOS、macOS→Windows），中间不折腾；每步都有“做不到就退”的分支。

---

## 总览

| 阶段 | 在哪 | 你要做什么 | 耗时 |
| --- | --- | --- | --- |
| A | Windows | 双击 `检查修复引导.cmd` → 双击 `安装到ESP.cmd`，UAC 点“是”，等绿字 | 2 分钟 |
| B | 开机 | F12 → OpenCore → macOS，等进桌面 | 2–5 分钟 |
| C | macOS | 跑一次采集脚本 + 按清单验收 + 再跑一次脚本 | 6–8 分钟 |
| D | 重启 | F12 → Windows Boot Manager，双击读取报告 | 2 分钟 |

**已经替你做完的**：EFI 制作、kext 替换、配置改写、ocvalidate 校验、文件完整性校验、安装脚本、备份/还原脚本、macOS 采集脚本。你只需要执行 A→D。

## 阶段 A：Windows 上安装（约 2 分钟）

### A0. 先检查/修复 Windows 引导（10 秒，这次必做）

双击 **`检查修复引导.cmd`** → UAC 点“是”。

- 显示 `BCD 完好` → 直接进 A1；
- 显示 `BCD 缺失` → 脚本会自动用 `bcdboot` 重建，看到 `BCD 已重建成功 ✔` 即可。

> **在 A0 没有显示“完好”或“重建成功”之前，先不要重启。**
> 如果重建失败，把窗口内容发我，我来给别的修法（例如用 Windows 安装 U 盘修复引导）。
>
> 如果双击报“路径中具有非法字符”之类：开始菜单搜索 `PowerShell` → 右键「以管理员身份运行」→ 粘贴：
> ```powershell
> & "D:\Users\12255\Desktop\new PLIST\一键安装\check-boot.ps1"
> ```

> 为什么多这一步：上次失败的输出显示备份卡在 `BCD`（Windows 运行时锁着它），而旧版还原用了完全镜像，可能把 ESP 上的 BCD 删掉。这一步先确认/修复，确保 Windows 一定能启动。新版安装脚本已经改成**只替换 `EFI\OC`**，不再碰 BCD / Microsoft / BOOT。

### A1. 双击安装

打开文件夹：

```
D:\Users\12255\Desktop\new PLIST\一键安装
```

双击 **`安装到ESP.cmd`** → 弹出 UAC 点 **“是”**。

脚本会自动：挂载 ESP → 备份 `EFI\OC` 到 `new PLIST\EFI-backup-original-<时间>` → 用新 OC 覆盖（**不碰 `Microsoft` / `BOOT`**）→ 校验哈希 → `ocvalidate` 校验 → 卸载 ESP。

### A2. 确认成功的标志

窗口最后应该出现：

```
 安装完成
 备份目录：D:\Users\12255\Desktop\new PLIST\EFI-backup-original-2026...
下一步：重启 → 开机按 F12 → 选择 OpenCore → 启动 macOS
```

中途任何一步失败，脚本会**自动用备份只还原 `EFI\OC`** 并红字提示；如果失败发生在备份阶段（还没动 ESP），脚本会直接停下、不做任何修改。

> 如果双击没反应 / UAC 没弹出：开始菜单搜索 `PowerShell` → 右键「以管理员身份运行」→ 粘贴执行：
> ```powershell
> & "D:\Users\12255\Desktop\new PLIST\一键安装\install-efi.ps1"
> ```
> 效果完全一样。

### A3.（可选）手动核对

不用做。想确认的话，脚本输出里这三行必须是绿的：

- `源配置 ocvalidate 校验通过`
- `文件哈希比对一致`
- `ESP 配置 ocvalidate 校验通过`

## 阶段 B：重启进 macOS（2–5 分钟）

1. 开始菜单 → 电源 → **重启**（不要“关机再开”，没必要）。
2. 开机出现 Lenovo logo 时**连按 F12**。
3. 启动菜单里选 **OpenCore**（可能显示为 `EFI`、`OpenCore`、`opencore` 之类）。
4. OpenCore 界面里选 **macOS** 回车。

### 首次启动会看到什么

- 会**跑代码（-v）**，比以前慢，这是正常的（我在 boot-args 里留了调试输出，方便定位）。
- 正常 1–3 分钟进桌面；慢的话 5 分钟也属正常。

### 卡住了怎么办（重要）

- **停在某一行超过 5 分钟不动**：手机拍下屏幕最后 5–10 行 → 长按电源键关机 → 开机 F12 → **Windows Boot Manager** → 回 Windows 双击 `还原ESP.cmd`（UAC 点“是”）。
- **OpenCore 菜单都进不去**：同样 F12 选 Windows Boot Manager → 还原。
- 还原后再把照片给我，我按日志定位，不会让你反复试。

## 阶段 C：macOS 里验收（6–8 分钟）

### C1. 先跑采集脚本（30 秒）

打开「终端」：`Command + 空格` → 输入 `终端` 或 `Terminal` → 回车。

**整段复制粘贴**（一次性执行）：

```bash
diskutil list | grep -i efi
sudo diskutil mount disk0s1
bash /Volumes/EFI/nred-check.sh
```

说明：
- 第一行只是确认 ESP 是哪个分区，正常会显示 `... EFI EFI ... disk0s1`；
- 第二行会要你输入**开机密码**（输入时不显示字符，正常）；
- 第三行跑完会打印 `报告已写入：/Volumes/EFI/EFI/OC/nred-report.txt`（这就是 Windows 里的 `S:\EFI\OC\nred-report.txt`，阶段 D 能直接读）。

如果提示 `Could not find disk: disk0s1`：把第一行输出里 EFI 那一列的分区名（比如 `disk1s1`）替换进去再执行。

> 万一 EFI 分区被挂成只读，脚本会把报告自动改存到桌面（会打印 `桌面副本`）。那就顺手把桌面上的 `nred-report.txt` 拷到 U 盘，阶段 D 改用 U 盘给我。

### C2. 对照清单打勾（每项 10–60 秒）

按顺序做，边做边在下面打勾，**不用重启**：

- [ ] **关于本机**：苹果菜单 → 关于本机 → 「更多信息…」→ 系统报告 → 左侧「图形卡/显示器」
  - 芯片组应是 `AMD Radeon RX Vega 8`（或 `AMD Radeon(TM) Graphics`）
  - VRAM 不应是 3 MB / 7 MB
  - 应有 `Metal 支持：Metal 3`（或 Metal 2/3）
- [ ] **透明与动画**：菜单栏、Dock、窗口阴影是否正常；启动台/最小化动画是否顺滑
- [ ] **Safari 硬解**：Safari 打开 YouTube → 任一 4K 视频 → 画质选 2160p
  - 同时开「活动监视器」（启动台 → 其他 → 活动监视器）→ CPU 标签
  - 看 `VTDecoderXPCService`、`WindowServer`、`kernel_task` 的 CPU：个位数～十几算正常硬解；飙到 60%+ 多半还是软解
- [ ] **本地视频**：有 4K HEVC/H.264 文件就用 QuickTime 播一下（没有可跳过）
- [ ] **花屏测试**：打开 Chrome / 微信 / QQ，看是否还有色块、闪烁、崩溃
- [ ] **亮度键**：按 Fn + 亮度键（或直接 F5/F6）看亮度是否可调
- [ ] **声音**：放首歌/视频，有声音即可
- [ ] **Wi-Fi / 蓝牙**：能连上即可（这两个我没动，应该和之前一样）
- [ ] **触控板 / 键盘**：点击、双指滚动正常
- [ ] **电池**：右上角电池图标显示百分比、能显示“正在充电”
- [ ] **睡眠（可选）**：合盖 10 秒再打开，能唤醒即可

> 有异常就记一句话（例如“Chrome 仍花屏”“亮度键无反应”），不用现在修。

### C3. 再跑一次采集脚本（10 秒）

把刚才 C1 的第三行再执行一次（**不用再挂载**）：

```bash
bash /Volumes/EFI/nred-check.sh
```

这次会把刚才测试期间的日志/崩溃记录一起写进报告，覆盖上一次。

## 分支处理（按现象选一条，不用全做）

### ① 完全进不去 macOS / 卡代码
F12 → Windows Boot Manager → 双击 `还原ESP.cmd` → 把卡住时的照片发我。

### ② 能进，但没有加速（显存很小、界面卡）
先别改任何东西，按 C1 跑报告；报告里 `sw_vers` 和 `ioreg NRed` 会告诉我原因。

### ③ 花屏/卡顿比之前更严重
说明显示补丁在当前小版本上不匹配。两个选择：
- 省事：双击 `读取诊断报告` 前，先用 `安装到ESP.cmd` 同目录的方式换回 `config-fallback.plist`（见下）；
- 精确：只去掉显示补丁——管理员 PowerShell 执行 `mountvol S: /S`，用 `D:\Users\12255\Desktop\ProperTree-master` 打开 `S:\EFI\OC\config.plist`，把 `boot-args` 里的 `-NRedDisplayFix` 删掉（保留 `-NRedVideoFix`），存盘重启。

### ④ 视频绿屏 / 播放器异常
同上，但改成删 `-NRedVideoFix`、保留 `-NRedDisplayFix`。

### ⑤ 亮度键无效
在 `boot-args` 末尾加 `NRedECFix=1`（同一个编辑方法），重启再试。

### ⑥ 想立刻退回旧配置（不改文件）
管理员 PowerShell：

```powershell
copy "D:\Users\12255\Desktop\new PLIST\EFI-optimized\OC\config-fallback.plist" S:\EFI\OC\config.plist
```

（`S:` 需先用 `mountvol S: /S` 挂载；这条只换配置，不换 kext。）

## 时间效率要点

1. **不要一项一重启**：C2 全部做完再跑一次脚本。
2. **先跑脚本再测试**：C1 是基线，C3 抓测试期日志，两份对比最准。
3. **卡住先拍照再断电**：照片比回忆可靠，5 分钟内不反复试。
4. **报告走 ESP**：macOS 写进 FAT32 的 EFI 分区，Windows 能直接读，不用 U 盘、不用截图。
5. **文档在 macOS 也能看**：macOS 能只读挂载 NTFS，Finder 里进 `D:` 盘就能打开本文件（若提示只读正常）。
