# 黑苹果核显加速修复包 · 说明（必读）

> **只想动手操作？直接看 [操作明细.md](操作明细.md)**，那里是一步步的清单；本文解释“改了什么、为什么”。

适用机器：**Lenovo 82MS / Ryzen 7 5800H / 核显 1002:1638（Cezanne，Vega 8）**
当前系统：**macOS 14 Sonoma（14.x）**
目标：让核显的 **Metal 渲染加速** 与 **VCN 视频硬解** 都正常工作，并修掉花屏/卡顿。

---

## 0. 一句话结论

你现在的配置不是“没装 NootedRed”，而是三个问题叠在一起：

1. **用的是上游 NootedRed 1.0.0** —— 它只有 Metal 渲染加速，**从来不做视频硬解（VCN）**，所以看视频仍然吃 CPU。
2. **SIP 全开**（`csr-active-config = 00000000`）—— 视频作者那套修复依赖“用户态打补丁”，SIP 全开时这些补丁会被系统直接挡掉，等于白装。
3. **缺少新方案的启动开关** —— `-NRedDisplayFix`（花屏/卡顿修复）和 `-NRedVideoFix`（VCN 硬解）都没加。

这三点我已经在 `EFI-optimized` 里改好，并且用与你的 OpenCore 同版本的 `ocvalidate` 校验通过（无任何报错）。

## 3. 安装步骤（Windows 下操作，约 3 分钟）

### 3.1 先备份现在的 ESP（必须）

以**管理员**身份打开 PowerShell：

```powershell
mountvol S: /S
robocopy S:\EFI "D:\Users\12255\Desktop\new PLIST\EFI-backup-original" /E
```

`S:` 只是临时盘符，如果被占用就换 `T:`。备份完确认 `EFI-backup-original\OC\config.plist` 存在。

### 3.2 复制新 EFI（合并覆盖，不会删掉 Microsoft 文件夹）

```powershell
robocopy "D:\Users\12255\Desktop\new PLIST\EFI-optimized" S:\EFI /E
```

> ⚠️ 不要用 `/MIR`。`/MIR` 会把 ESP 里的 `EFI\Microsoft`（Windows 引导）一起删掉，导致 Windows 进不去。`/E` 只覆盖同名文件。

复制完检查：

```powershell
Get-Item S:\EFI\OC\config.plist | Select-Object LastWriteTime
Get-ChildItem S:\EFI\OC\Kexts | Select-Object Name
```

应该看到 `NootedRed.kext` 和 `NootedRed-1.0.0.kext` 两个都在。

### 3.3 重启

开机按 **F12** → 选 OpenCore → 选 macOS。第一次会带 `-v` 跑码，**比平时慢是正常的**（`debug=0x100` 会拖慢启动）。

## 4. 进系统后：先确认版本，再确认驱动

打开“终端”，逐条执行：

```bash
sw_vers
```
> 期望：`ProductVersion: 14.x`。记下 `BuildVersion`（如 `23J631` 或 `23E214`），第 7 节要用。

```bash
system_profiler SPDisplaysDataType | grep -Ei "Chipset Model|VRAM|Metal|Resolution"
```
> 期望：出现 `AMD Radeon RX Vega 8`（或类似）、VRAM 不是 3MB/7MB、`Metal: Supported`。

```bash
ioreg -l | grep -i "NRed" | head -30
```
> 期望能看到 `NRedDisplayFixVersion=3`、`NRedFVRCEnabled=1` 之类的属性。**如果一条都没有**，说明 fork 没加载，直接跳到第 6 节回退。

```bash
kextstat | grep -i nooted
```
> 期望有一行 `org.Chefkiss.NootedRed`（大小写可能不同）。

## 5. 怎么验证“硬解真的生效了”

1. **Safari 打开 YouTube 4K 视频**（Safari 走 VP9/AV1），同时开“活动监视器”看 `VTDecoderXPCService` 和 `kernel_task` 的 CPU：
   - 硬解生效：CPU 占用低（个位数～十几），画面流畅；
   - 没生效：CPU 明显飙高、风扇转。
2. **本地 HEVC/H.264 4K 视频**用 QuickTime 播放，同上观察。
3. 再看属性：
   ```bash
   ioreg -l | grep -E "NRedVP9Probe|NRedVP9State|NRedVP9Applied|NRedVCN"
   ```
   - `NRedVP9Probe=1` = 能力已发布；`NRedVP9State=1` = 已启用；
   - `=0/2/3/4` = 后端没装成/未就绪/校验失败/写失败 → 说明你这版系统的函数签名和 fork 的参考数据（14.8.9）对不上，见第 7 节。

> 注：fork 的硬解只覆盖 **VP9（含 10-bit）** 和它已接的 H.264/HEVC 解码路径；**FairPlay 受保护视频（Apple TV、Music 里的版权内容）仍会黑屏**，这是作者写明的已知限制，不是你没配好。

## 6. 出问题怎么退（两条路，都不用重装）

### 路线 A：只换回旧版 NootedRed（保留其它修复）

1. 把 `EFI-optimized\OC\config-fallback.plist` 复制到 ESP，改名覆盖 `config.plist`：
   ```powershell
   copy "D:\Users\12255\Desktop\new PLIST\EFI-optimized\OC\config-fallback.plist" S:\EFI\OC\config.plist
   ```
2. 重启。这个配置用回 NootedRed 1.0.0，并去掉了 `-NRedDisplayFix -NRedVideoFix`。

### 路线 B：完全恢复原样

```powershell
robocopy "D:\Users\12255\Desktop\new PLIST\EFI-backup-original" S:\EFI /MIR
```
（备份里包含 `Microsoft`，所以 `/MIR` 是安全的完整还原。）

> 如果改完**连 OpenCore 都进不去**：开机 F12 直接选 `Windows Boot Manager` 进 Windows，再按路线 B 还原即可，Windows 不受影响。

### 常见现象对照

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 跑码后卡住/黑屏 | SIP 值写错、或 NootedRed 不兼容当前 14.x 小版本 | 用路线 A 回退，再按第 7 节升级系统 |
| 能进系统但 `ioreg` 里没有 NRed | fork 没加载（Lilu 版本或 csr 没生效） | 确认 `csr-active-config` 显示 `430A0000`；确认 Lilu 1.7.2 |
| 有 Metal 但视频还是软解 | 系统版本 ≠ 14.8.9，视频补丁被校验拒绝 | 第 7 节 |
| Chrome/微信仍花屏 | 显示补丁没命中，或旧缓存 | 先删 `~/Library/Caches` 里对应 App 缓存；仍不行用你 README 里的 **GLFriend** |
| 开机变慢 | `debug=0x100` + `-v` | 稳定后把 boot-args 里的 `-v debug=0x100` 删掉，只留 `keepsyms=1 npci=0x3000 -NRedDisplayFix -NRedVideoFix` |

### 想定位是哪个开关的问题（可选）

两个开关是独立的，可以拆开试：

- 花屏/卡顿变严重 → 删掉 `-NRedDisplayFix`，只留 `-NRedVideoFix` 重启；
- 视频能播但播放器异常/绿屏 → 删掉 `-NRedVideoFix`，只留 `-NRedDisplayFix` 重启。

改 `boot-args` 用 ProperTree 或 OCAT，改完存盘再重启；不确定就用 `config-fallback.plist` 先退回去。

## 7. 重要前提（决定你能不能吃到硬解）

fork 的显示/视频补丁是**按 macOS 14.8.9 / 23J631 的真实系统缓存做的校验数据**。它的机制是“先逐个核对函数字节，对不上就拒绝这一项”，所以：

- **14.8.x（23J631 附近）**：数据完全对得上，硬解/显示修复最可能全部生效。
- **14.0–14.7（比如 23E214）**：Metal 基础加速不受影响；但显示/视频补丁里**对不上的那几项会被拒绝**（不会把系统改坏，只是该项不生效）。GPU 驱动在同一大版本内通常变化不大，所以可能只挂掉少数几项，具体看 `ioreg` 里的 `Applied` 状态。
  - 想最大化命中率：升级到 **14.8.9**（Sonoma 最后一个版本）。你的补丁 `MaxKernel=23.99.99` 正好覆盖到它。
  - 升级前先确认这份 EFI 能正常启动，再升级；升级后首次启动仍走 OpenCore。

另外两点必须知道：

1. 这是 **pre-release（实验版）**，作者自己写了“会有崩溃”。所以务必保留第 3.1 节的备份和 `config-fallback.plist`。
2. 你这台是 **Cezanne（1638）**，正好在 fork 支持列表里（`15E7 / 1636 / 1638 / 164C`），方向没问题。
